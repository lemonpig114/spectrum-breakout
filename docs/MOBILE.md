# Android 触屏测试

## 战斗视野

安卓及 `--mobile-controls-test` 的 Camera2D 最终缩放为1.3，较电脑1.0把角色、敌人、地图放大30%。开场拉远动画和继续存档都收敛到这个倍率；HUD、菜单、摇杆和触点坐标不缩放。可视范围内索敌/掉落保护继续使用实际相机缩放，不会把视野外目标误算进来。v0.2.0已导出Android包；桌面模拟不等同手机实机验收。

## 当前操作

- 左下区域按下时在触点生成摇杆，默认本次操作期间基座不移动，松手隐藏；在暂停 → 设置可开启基座跟随，设置会保存在手机本地。摇杆有 10 px 死区，跟随模式拖过外环时基座缓慢跟随。
- 另一根手指在战斗区域轻点：切换到下一个颜色。左右横滑：选择上一个或下一个颜色。长按：查看切色轮盘；不选择方向就松开会取消。
- 手机端自动索敌、自动射击，没有左键手动瞄准，也没有额外的战斗按钮。右上角和安卓返回操作均可暂停；切到后台时自动暂停。桌面键鼠操作不变。
- 商店、升级、祭坛、遗物选择等面板沿用触摸模拟鼠标点击；手机和电脑显示不同的设置项及操作提示，遗物选择按钮加大。
- 手机上缘 HUD 留出状态栏空间。蓝色降低绿通道，避免高亮时视觉变青。

## 测试顺序

1. 先在电脑端运行 `res://tests/mobile_controls_test.tscn -- --mobile-controls-test`。脚本覆盖触点生成且基座不跟随、可选跟随、死区、满速、双指同时操作、轻点、左右滑、长按取消、暂停松手、安卓返回与切后台、禁止触屏手动瞄准。
2. 在 Godot 的运行参数中添加 `--mobile-controls-test`，用鼠标单指体验摇杆出现位置和视觉。电脑鼠标不能真实模拟两根手指的触感；双指逻辑由上述自动化测试验证。
3. 把 `build/v0.2.0/spectrum-breakout-v0.2.0-android-arm64.apk` 复制到 ARM64 安卓手机并安装。测试实际多点触控、摇杆响应、按钮大小、刘海安全区、画面效果及 180 秒后的帧率和发热。手机端验收后再微调死区、半径、跟随速度与画质。
4. 导出前用 Android preset 生成 `.pck`，通过 `--main-pack` 运行 `smoke_test` 和 `menu_test`。必须确认导出包能加载角色、敌人、技能、遗物，并且实际刷怪。单独跑编辑器里的测试不足以发现导出资源扫描错误。

## 导出记录

- Godot 4.4.1 的 Android 34 SDK、构建工具与导出模板已配置；项目开启 ETC2/ASTC 导入。桌面保持 Forward+，安卓使用 Godot 默认的 Mobile 渲染器。`ContentDB` 使用 `ResourceLoader.list_directory()` 读取导出包内资源；旧版 `DirAccess` 扫不到转换后的资源，导致选角跳过、敌人/技能/遗物为空。
- 本机 `export_presets.cfg` 和 `build/` 已忽略，避免把调试签名文件与将来可能加入的发行签名信息提交到公开仓库。
- 调试 APK 为 ARM64、清单最低 API 21、目标 API 34、固定横屏；所用 Mobile/Vulkan 渲染器实际应在支持 Vulkan 的 Android 9+ 手机上测试。签名由 `apksigner verify` 确认。此包用于实机测试，不是商店发行包。

- 2026-10-30：v0.2.0，versionCode2，ARM64调试签名APK；保留原包名和签名，加入世界1.3倍相机缩放。实际APK提取的资源通过桌面smoke/menu检查，v1/v2/v3签名有效。下载入口见README。
